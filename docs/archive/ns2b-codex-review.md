## Limits that remain

- Private is not file protection: a coding agent whose working folder holds a notebook can read it with its own tools.
- F05: teardown checks each mirror path for links and then removes by path, so a junction swapped in between could redirect a removal.
- A digest whose named source was removed from the registry has no folder to judge, so it reads as missing, not withheld.
- A source's file-level exclude glob that matches Markdown pages inside a notebook it covers leaves those pages unindexed.
- A copy recreated in the vault while a ticked deletion is being applied becomes a new page at the next sync.
- Refused rows still weigh query words in the vocabulary; each call may pass the page index budgets by one notebook walk and one page.
- The round 3 fixes were not re-reviewed by Codex.

## Codex's report

### Round 1

#### 1. Summary

Commit `5723a24` has release-blocking privacy and vault sync defects. A folder alias can bypass private policy, and an explicit registration can override the vault mirror exclusion. Mirror sync can retain private page bytes in the vault, advance its baseline after skipping a write, or apply a deletion after the vault copy returns. Page retrieval also has persistent freshness and ranking failures. The review is static. No files changed and no tests ran.

#### 2. Severity scale

| Severity | Meaning |
|---|---|
| Critical | Broad or irreversible exposure or data loss through a routine operation. |
| High | Private content exposure, unintended canonical writes or deletions, or a bypass of a central privacy control. |
| Medium | Persistent stale or missing results, metadata exposure, misleading status, or a failure that needs manual recovery. |
| Low | A bounded validation, output, or documentation defect. |

Effort is **S** for a local change, **M** for a change across code paths, and **L** for a lifecycle or storage change. Estimates include targeted regression tests.

#### Prioritized fix roadmap

1. Fix visibility and authorization first. Cover deleted digests in secondary roots, the prompt title fallback, retargeted roots with identical file fingerprints, and backward recovery of a registry change.
2. Fix vault writes and teardown next. Cover concurrent saves, interrupted preservation, parent swaps, unsupported hard links and stale plans. Verify plain `sync` followed by teardown on a vault with no notebooks, then verify teardown inspection and retry on a vault with notebooks.
3. Fix retrieval completeness and progress. Share provenance checks across search, listing and ingest. Deduplicate before limiting results, then test partial source coverage, domain moves, unreadable folders, vector backfill and the prompt deadline.
4. Close the remaining approval and registry cases. Test a recently recreated copy, a malformed plan with plausible fields, and duplicate rows that match the requested policy.
