# Recovery and history

Every canonical/configuration mutation records preimages, postimages, hashes, and durable intent under STORE/.operations/OPERATION/journal.json before writes. A single OS store lock serializes cooperating writers. A crash can leave a partially applied operation; it is recoverable, not instantly atomic across the entire filesystem.

Run `doctor` to discover pending operations, `history` to inspect receipts, and `recover OPERATION --direction forward` to finish or `--direction backward` to restore. Recovery preflights every touched path against known pre/post hashes before the first write, preserves unknown user edits, validates journal content, and can resume after another interruption. Rebuild derived indexes/views after external repair; CLI recovery attempts reconciliation for affected domains. Canonical Markdown remains authoritative if derived regeneration fails.

A completed operation can be reversed through `undo OPERATION`, followed by inspection and approved application of the resulting plan. It rejects later conflicting edits. Keep journals/backups private: they contain historical note and configuration preimages. Maintenance telemetry reset does not delete these recovery records. The only journals ever deleted automatically are committed Obsidian sync bookkeeping (`overlay_views`, `overlay_sync`, `overlay_state`) older than 14 days, at most once a day from session housekeeping.

Journals cover script operations, not the store folder itself. `backup` writes a verified zip of the canonical set (notes, archives, bindings, taxonomy, schema version; no indexes, journals or turn state) to STORE/backups and keeps the newest 7. Session housekeeping takes one at most daily (Claude SessionEnd, Codex SessionStart), and `doctor` warns when none is newer than 48 hours. Backups live inside the store, so copy `backups/` elsewhere or keep the store under git to survive losing the whole folder. `restore-plan FILE` turns a snapshot into an exact-hash plan for the domains it contains: review it with `inspect-plan`, then `apply`; it is journaled, so `undo` reverses it. Members outside the canonical set are rejected.

Package install recovery is rooted at the install folder (`%LOCALAPPDATA%/agentic-living-memory` on Windows, `~/.local/lib/agentic-living-memory` elsewhere; the parent of `app/`). Harness wiring is rooted at each harness home, and legacy retirement at CODEX_HOME. Use `living_memory.py --root FOLDER history` and `recover` in the matching folder. The standalone installer lifecycle retains legacy receipts, durable package intents, and restartable rollback; rerunning its approved Python API plan resumes an interrupted operation. Receipt paths and hashes must remain intact.

Do not edit ownership records to suppress conflicts. Save and review modified files, then create a new plan. Corrupt JSON is preserved and reported rather than replaced. Recovering an older version may also require its compatible store schema; this migration intentionally preserves canonical note bytes.
