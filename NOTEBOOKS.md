# Notebooks

Notebooks hold pages: free-form Markdown the user writes, mostly in Hivemind's Notes Studio. Pages are a record kind of their own. They are not notes, so no list, review, maintenance, SessionStart, recap or wiki path reads them, and they need no frontmatter or tags. `search` and `ask` list them apart from notes, in a `pages` array. The design is in `docs/notebooks-design.md`.

## Layout

```
domains/D/notebooks/<notebook>/
  notebook.json            title, order, icons, pins, visibility, private, uid
  <section>/<page>.md      pages, nested up to 8 levels; a page's subpages sit in a folder of the same name
  assets/<sha8>-<name>     attachments, added with doc attach
  .proposals/<id>.json     edits agents staged for the user
```

- A notebook id is 2 to 40 lowercase letters, digits or hyphens. Page names end in `.md`, are unique ignoring letter case within a folder, and may not use `/ \ : * ? " < > |`, control characters, Windows device names, or a leading or trailing space or trailing dot. `notebook.json`, `assets` and `.proposals` are reserved at the top of a notebook.
- A page is kept byte for byte: CRLF, a BOM and a missing final newline all survive. Its revision is the SHA-256 of its bytes.
- Limits: a page is at most 4 MiB, an attachment at most 25 MiB; a notebook holds at most 20,000 pages and 2 GiB of attachments (doctor warns at 80%).
- Links and junctions inside a notebook are refused; Living Memory never follows one.

## Commands

Every write is one journaled operation (`doc-...`) and `doc undo OPERATION` (or `undo OPERATION`) reverses it, bringing a page back byte for byte even when an editor had left it in an encoding other than UTF-8. No write may delete a notebook's `notebook.json` while the notebook keeps other files, so undoing the creation of a notebook that has pages is refused: delete the notebook as a whole.

| `doc notebook update D NB [--expected-revision R] [--title] [--visibility] [--private\|--no-private] [--order-file F] [--icons-file F] [--pinned-file F] [--settings-file F]` | Change its settings |

| `doc read D NB PATH [--max-chars N]` | A page's text and revision |
| `doc read --file PATH [--max-chars N]` | The same for a Markdown page of a registered folder notebook: `origin: folder`, `domain`, `notebook` (the `nb-` id), `folder`, `path` (inside the folder), `file`, `text`, `revision` (sha256 of the bytes, as `search` gives it), `size`, `updated`. A private folder reads as not found |
| `doc create D NB PATH [--body-file F]` | Create a page (text from the file or stdin) |

| `doc attach D NB --from-file F [--name N]` | Copy a file into `assets/`; the same bytes under the same name are reused |

The proposal is kept at `domains/D/folder-proposals/NB/ID.json` with the page as it was read (`base`, up to 1 MiB) so Hivemind can merge against it |
| `proposals [list] [--kind note\|page\|all] [--status pending\|accepted\|rejected\|all] [--domain D] [--notebook NB]`, `proposals show ID` | Staged page edits (12 hex digit IDs; each row has `kind: page`) and staged notes (8 digits; `kind: note`) |
| `proposals accept ID [--expected-revision R]`, `proposals accept ID --edited [--expected-revision R]` (body from `--body-file` or stdin), `proposals reject ID [--reason TEXT]` | Settle a staged page edit (main actor). `--edited` writes the user's merge of it instead and settles it as accepted and edited in one operation; the page must be at `R`, or not exist when `R` is left out. The merge must be given (a terminal or a serve request without stdin is refused) |

| `doc tasks [--all-domains] [--notebook NB] [--open]` | Task lines (`- [ ]`, `- [x]`) of Living Memory notebooks with page, line, `text` (as written), `task` (as shown), `due`, `owner` and `priority`; see [Tasks](#tasks) |
| `doc query --payload-file F [--all-domains]` | Pages by frontmatter properties: `{"where": [{"key", "op", "value"}], "sort": [{"key", "order"}], "limit": N, "notebook": NB}`; `op` is `=`, `!=`, `<`, `<=`, `>`, `>=`, `contains`, `exists` or `missing`, numbers compare as numbers, and `title`, `path` and `notebook` work as keys |
| `doc folder set PATH [--visibility V] [--private\|--no-private]`, `doc folder unset PATH [--forget]` | Register a folder notebook outside the store and how far agents reach into it (Hivemind runs these) |
| `domain create NAME --notebook-only` | A domain that holds notebooks only |

## Who may do what

- Agents read pages (`doc notebooks`, `list`, `read`, `history`, `search`, `tasks`, `query`; `proposals list` and `show`) and stage edits with `doc propose`. Every other `doc` action, an unknown one included, and `domain create` are the main actor's: the hook denies them to subagents, never auto-allows them, and denies them to agents in a Hivemind terminal (`HIVEMIND_SESSION`). The hook also denies `serve` to agents, since its requests carry arguments the hook never sees.
- Visibility: a `hidden` notebook is listed only with `--include-hidden`, searched by `doc search` only when `--notebook` names it, and never found by `search` or `ask`. A `searchable` one (the default) is found by `search`, `ask` and `doc search`. An `injectable` one is also offered to the prompt hook (see below).
- Private notebooks look missing to every command, writes, `apply`, `undo` and `recover` included, unless it carries `--include-private`, which only Hivemind's own bridge passes. `doctor`, `backup` and relocation previews count entries inside private notebooks (`private_withheld`) without naming them; `doctor --include-private` names them. Inside `batch` the flag is refused, because the hook sees only the outer command. The hook denies `--include-private` to any agent, and denies Read, Glob and Grep on a private notebook's folder (or a search over a folder that holds one). `history` (note history too), `doc history`, `diff` and `inspect-plan` leave out changes inside a notebook that is or ever was private (`notebook-privacy.json` keeps them, and neither undo nor restore removes an entry). Private is not file protection: a shell command can still read the files.

## Folder notebook pages

- `doc read --file` and `doc propose --file` take the path of a `.md` or `.markdown` file under a registered, not removed folder (the nearest one wins). A link or junction on the way is refused. A hidden folder can be read and proposed to by naming the file, as a hidden notebook can by name; a private one looks missing without `--include-private`.
- The hook refuses an agent's Edit, Write, MultiEdit, NotebookEdit or apply_patch on such a page and says to read it with `doc read --file` and stage the edit with `doc propose --file`; for a private folder it says agents may not change it. The rule covers every agent session, Hivemind's or not (`runtime.FOLDER_GUARD = 'all'`). The registry is cached by its modification time, since the hook runs on every edit.
- Not covered: shell writes, copies of the folder (a git worktree stays a code diff), folders known only from a `.hivemind` sidecar and sessions that turned Living Memory off. A damaged `notebook-folders.json` guards nothing until `doctor` repairs it.
- `proposals accept ID` settles the record first (`doc_accept`, journaled, with the new bytes' `revision`), then writes the page with the same safe write the Obsidian mirror uses: CRLF and a BOM are kept exactly, and a save made meanwhile is never overwritten. A page that changed since the proposal's base revision is refused (`stale_revision`, exit 6); with `--edited` the page must be at `--expected-revision` instead, and the record keeps the bytes the merge replaced (`previous`). If the write finds the page changed, the settlement is undone and the accept is refused. Running `proposals accept ID` again on an accepted proposal whose page was never written finishes the write. A proposal whose folder is no longer registered is `orphaned`: it can be rejected, not accepted.
- `undo OPERATION` on a folder `doc_accept` puts the old bytes back while the page still holds what the accept wrote (a new page is deleted again), then sets the proposal back to pending. After a later change to the page it is refused and says to restore the page from Hivemind's file history. A second undo, or an undo of the undo, changes nothing; accept the proposal again instead.
- `history` hides these operations unless `--include-private` is given: the records hold page text from outside the store. `doc undo` handles them.

## Search and reach

- Living Memory pages are indexed in `domains/D/docs.sqlite3`, derived and never backed up (`doc search --rebuild` recreates it). Every `doc search`, `doc tasks`, `doc query`, `search` and `ask` first checks the notebooks for changed pages for at most 0.2 seconds, resuming where the last check stopped, then reindexes for at most 0.5 seconds; a reply that left work over says `pages_stale: true`. Each call still finishes one notebook and one page past those limits, so it always makes progress (with several domains, they take turns, recorded in `hooks/docs-allowance.json`). A page that cannot be read keeps `pages_stale` true and is retried after the others; a folder that cannot be listed keeps the pages under it until it can be. A `doc` write reindexes its own notebook at once. The prompt hook never reindexes.
- Each page hit has `origin` (`lm` or `folder`), `domain`, `notebook`, `notebook_title`, `title`, `path`, `heading`, `snippet`, `line_start`, `line_end`, `revision`, `score`, `relevance` and `label: notebook page`. `ask` gives each question of a several-question query its own `pages`. A Living Memory page's frontmatter is left out of its snippets; a folder page is chunked like any source file, so its snippet can show frontmatter lines. Credentials are redacted as in sources.
- Private notebooks are searched only with `--include-private` (Hivemind's bridge). Whether a notebook is private or hidden is read from its `notebook.json` when results are served, so a change takes effect at once.
- Folder notebooks are folders outside the store that Hivemind opens as notebooks. `doc folder set` records one in `notebook-folders.json` with its domain, visibility and private flag; its sidecar `.hivemind/notebook.json` (`visibility`, `private`, `title`) is a second opinion, and the stricter of the two wins (private, then hidden, then searchable, then injectable). A sidecar that cannot be parsed counts as hidden; a folder inside a notebook takes the strictest policy above it. `doc folder unset` of a hidden or private folder keeps its entry as a tombstone, so the folder stays out of reach even where the sidecar was never written; `--forget` drops it. `set` keeps a tombstone's private flag unless `--no-private` is given, and without `--visibility` it keeps the entry's or tombstone's visibility (a new folder is searchable; capability `docs.folder_policy` 2), and a restore never replaces a live entry with a less strict one. Folders are judged by their resolved path, so a link or junction to a private folder reaches nothing in it. `set` refuses a folder that is, holds or lies inside the Obsidian vault Living Memory manages. Of two registry rows for one folder (an alias, a hand edit), the stricter counts for reads, `set`, `unset` and restore alike. The registry and the mirror state are Hivemind's bookkeeping: `history`, `diff` and `inspect-plan` show them only with `--include-private`. An undo, plan or restore that would make a hidden or private folder less strict needs `--include-private` too; other changes to them do not.
- Folder notebook pages are indexed by the knowledge base (`core/sources.py`): by a source without include globs that already walks the folder, else by a source of their own named `nb-` and a hash of the path (a page that two sources index is served once). Hidden and private notebooks are never walked. Each hit is checked again against the registry and sidecars when it is served, so a notebook made hidden or private disappears before the next sync, and its rows go at that sync; a source whose link or junction now leads elsewhere serves nothing until it is synced again, and that sync reads every file afresh. A source with include or exclude globs inside a notebook does not stop the notebook's own source from walking that folder too. A folder notebook moved to another domain is served only by the domain the registry names. `search --sources`, `ask`'s `sources` and `ingest-scan` leave every notebook file out, and `--source` refuses a file in a hidden or private notebook. A digest made from a file before its notebook turned hidden or private is withheld: search, ask and the prompt hook show a WITHHELD notice and the title "Withheld note" in its place until the user reviews it, also when the file has since been deleted (the note itself stays memory). `search --file` withholds it the same way. A damaged `notebook-folders.json` (unreadable, or a row without an absolute path, with an unknown visibility or a private flag that is not true or false) stops `source-sync`, serves no source excerpt or folder page and withholds every digest made from a file until doctor's warning is acted on. `sources` counts only the files of notebooks that are searchable or injectable now, and says `folder moved` for a source whose link now leads elsewhere.
- Prompts: the prompt hook's source excerpt channel (at most two excerpts, 800 characters, only when notes gave fewer than two answers, never for subagents or machine prompts, each excerpt once a session) also takes excerpts of injectable notebooks: folder notebooks of the session's domain, and Living Memory notebooks of the session's domain and its parent and child domains. Each is labelled `[notebook TITLE]`. Searchable notebooks are never injected, and SessionStart shows no page text; its Overdue line may name an overdue task of an injectable page (see [Tasks](#tasks)).

## Tasks

- A page line `- [ ] text` or `- [x] text` is a task (the bullet may also be `*`, `+` or `1.`), outside fenced code and frontmatter. It has three optional fields, read by the rule that also reads the action items of notes (`item_fields` in `core/note_format.py`): `due` (`YYYY-MM-DD`), `owner` and `priority` (`highest`, `high`, `medium`, `low` or `lowest`).
- Write them as a tail at the very end of the text, in any order: `- [ ] Call Sam (due: 2026-12-01, owner: me, priority: high)`. A field the tail does not give validly is read from the text: `due` from the first `📅 2026-12-01` or `due:: 2026-12-01`, `priority` from the first of `🔺` (highest), `⏫` (high), `🔼` (medium), `🔽` (low) or `⏬` (lowest). `owner` is the tail only. When both forms are there, the tail wins. A bad value is ignored. Changing a page's tasks is a page edit (`doc propose`), not an `update --item`.
- `text` is what follows the box, cut at 500 characters; the fields are read from that text. `task` is the text people read: `text` without the tail, a `📅 date`, a priority emoji and a `✅ date`. The cases are in `tests/fixtures/task_lines.json`, which Hivemind copies and runs through its own parsers.
- `open` lists open page tasks beside the open action items of notes, as rows with `kind: "page"`, `domain`, `notebook`, `path`, `title`, `line`, `item`, `task`, `due`, `owner`, `priority` and `overdue`; a page task has no `ref` or `index`, and is ticked by editing its page. `--pages injectable` (the default) takes the injectable notebooks of the domain and its parents (Living Memory ones and registered folder notebooks), `--pages searchable` also the searchable ones and `--pages none` leaves page tasks out. Hidden and private notebooks never show. `--tag` lists no page tasks (they have no tags). `--due-by`, `--owner` and `--sort due` apply to both kinds. `pages_stale: true` says the page index was left unfinished, as for `doc search`.
- Registered folder notebooks join `docs.sqlite3` beside the Living Memory notebooks, named `nb-` and ten hex digits of the folder's path as in the knowledge base. Only their task and property rows are stored there, with no chunks, search text, vocabulary or vectors, since their search comes from the knowledge base. Their walk skips dot folders (`.hivemind`, `.obsidian`), links and pages over 1 MiB. Only `open` and SessionStart serve them from this index (`doc tasks`, `doc search`, `doc query`, `search`, `ask` and the prompt hook still serve Living Memory notebooks from it, and folder pages from the knowledge base). Each page is judged when it is served by the strictest policy over its folder and the folders above it (registry and sidecars), so a hidden or private subfolder never shows, whatever the index holds. The index has `VERSION` 2 (the task table gained `owner` and `priority`); an index of another version is replaced on the next refresh.
- SessionStart reads the page index as it is and never indexes: the Overdue line also counts and names (as `path:line`) overdue open tasks of injectable pages, and an unreadable, missing or older index shows none.

## Obsidian

In a domain with a managed vault, each searchable or injectable notebook is mirrored byte for byte to `<vault>/Notebooks/<domain>/<notebook>/` at every vault sync (`sync`, `overlay-build`, `overlay-sync-all` and the hooks' syncs), attachments under `assets/`. Hidden and private notebooks are never mirrored; when one turns hidden or private every file of its mirror leaves the vault at the next sync: a page edited or added in the vault is kept as a proposal first, any other file as an attachment of the notebook named `from-obsidian`. The Sync Status page names only notebooks mirrored now, and `sync` rewrites it too.

- A page edited in the vault comes back after the quiet period as a page write against the revision last mirrored. If the page changed in memory too, the vault text becomes a proposal and the vault shows the memory version again; the Sync Status page says so.
- A new `.md` file in a mirrored notebook becomes a page. A name pages may not use is listed under "Notebook pages" on the Sync Status page.
- A page deleted in the vault becomes a delete plan: tick its "Delete page" line on the Sync Status page and the next sync applies it, as long as the copy is still gone. If the copy is back by the time the tick is applied, the tick lapses. Five or more copies missing at once (and at least a fifth of them, deletions waiting for a tick included) count as a vault reset: they are copied back instead, and no tick applies.
- Each vault file is changed only while it still holds what the sync read, so a save in Obsidian during a sync is picked up by the next one; a file found changed is put back, or, when a newer save is already there, kept beside it as `NAME (kept TIME)`. A folder that cannot be listed is left alone until it can be. The mirror never follows a link or junction in the vault and keeps no journal there, `overlay-teardown-plan` included: `inspect-plan` lists the notebook copies a teardown removes, a stale teardown removes none, and copies left behind (changed or in use) are named in the receipt's warnings. A domain that moves to another vault starts its mirror afresh and removes the unchanged copies from the old one, and a file already kept in memory is not kept again when its removal is retried; `overlay-teardown-plan` removes the mirror with the rest of the overlay.
- Attachments flow from memory to the vault only.
- The vault's `Notebooks` folder is never indexed as a source, and agents may not write it. A notebook-only domain has no vault, so its notebooks are not mirrored.

## Notebook-only domains

`domain create NAME --notebook-only` makes a domain with no folder binding and no notes; run again, it recreates a missing `domains/NAME/notebooks` folder. `capture`, `propose` and `bundle` import refuse it; `unbind` refuses while it holds pages; `domains` reports its `kind` as `notebook`. `bind NAME FOLDER` turns it into an ordinary domain, keeping its notebooks; if that stops half way, run the same `bind` again.

## Journals, backups and relocation

- An attachment is a blob effect: the journal keeps only hashes, and the operation keeps both sides' bytes in `.operations/<op>/blobs/<sha256>` until retention deletes it, so an attachment takes twice its size meanwhile. The asset file is replaced in one step and always holds one side.
- Retention: a finished notebook operation is deleted once it is not among the newest 100 operations of any file it changed, or once it is older than 90 days. It runs with the daily journal pruning.
- Snapshots carry `manifest.json` (version 2) listing the notebooks they cover. A restore over a page that has since become a folder, or the reverse, is refused before anything changes, with the path to move. Attachments are stored uncompressed. Automatic snapshots leave out attachments past 500 MB and list them as `omitted`; `backup` takes everything. A restore never touches a notebook the snapshot does not list, never deletes an omitted attachment, keeps the live binding of a domain that still holds such a notebook, and only adds to `notebook-privacy.json`.
- Relocation copies notebooks and leaves out every derived index (`search`, `sources`, `vectors` and `docs` SQLite files with their `-wal`, `-shm` and `-journal` files, and their `.sources-`, `.vectors-` and `.docs-` temporary files). `notebook-folders.json` is backed up and restored like the privacy registry.
