# Maintenance

There are no background engines, and nothing is sent anywhere. The only usage records are a local diary and an operational log (see below). Maintenance is the notes themselves plus a few explicit commands:

- `validate` reports notes that fail to parse and duplicate IDs. `doctor` reports those too, plus operations that never finished (with the `recover` command), journals that cannot be read, and under `hooks.wiring` whether each wired harness's hook interpreter and adapter script still exist. Run from the installed copy, it also says whether the handlers and the managed instruction block are current. A missing interpreter or script makes `ok` false and the warning gives the `integrations/setup.py HARNESS --hooks` command to run.
- `remap-plan` moves notes between domains with stable IDs as a reviewed, undoable plan.
- `merge-plan`, `retag-plan` and `taxonomy-plan` handle bulk changes through reviewed plans.

**Usage diary.** `.turns/usage-YYYY-MM-DD.jsonl` (one file per UTC day) records which notes memory showed (`inject`: at session start, on a prompt, or as a file hint) and which were then used: `read`, `update`, `check`, `supersede`, `confirm`, or `duplicate` when a capture re-stated a saved note. It also records each prompt-time nudge and each Stop reminder by kind (`reminder`) and each note saved on a turn whose prompt carried a durable statement (`signal-capture`). Each line holds only the event, the note ref, a 12-character session hash, a kind and a UTC time. There is no prompt text, title or body. The diary stays on this machine. Days older than 30 are removed with the rest of `.turns/`, and deleting the files by hand loses nothing canonical. `stats [--days 30]` reads it: notes injected 3+ times and never used (candidates for a sharper title or an archive plan), the most-used notes, reminders by kind and signal-turn captures per ISO week. Reads by subagents are logged too; that is a sidecar write, and notes are untouched.

**Operational log.** `logs/log-YYYY-MM-DD.jsonl` (one file per UTC day) has one JSON object per line. Each line has `ts`, `level`, `kind`, `event` and `pid`. `kind` is one of:
- `hook`: a hook run, with `harness`, `domain`, a 12-character `session` hash, `ms`, `outcome` (which of context/deny/allow/continue_reason/warning/instructions it returned) and `context_chars`.
- `command`: a script command, with `actor`, `domain`, `ms`, `exit_code`, and `error` `{code, message, reason}` on failure. `reason` is the message's leading snake_case token, such as `stale_revision`, `possible_duplicate`, `private_content` or `ambiguous_ref`.
- `internal`: an exception that housekeeping deliberately absorbs (vault sync, daily backup, pruning, provenance, file hints, recall, usage diary, index reconcile). It carries `error` `{type, message, frames}`.

There is no prompt text, injected context, title, body or command argument. Exception messages are kept, capped at 300 characters with credentials redacted, so they can name a path or a note title. Tracebacks are kept only as `file:line function` frames. `LIVING_MEMORY_LOG_LEVEL` sets the lowest level kept: `debug`, `info` (the default), `warning`, `error` or `off`. Read-only app (`--actor viewer`) commands log at `debug`. Days older than 30 are removed once a day by session housekeeping. Backups skip the folder, and deleting it loses nothing canonical. `logs [--level L] [--kind K] [--event E] [--days 1] [--limit 50]` reads it newest first, and `doctor` reports `logs` (counts for the last 7 days, the last error and the `content` state) and warns about recent errors.

**Decision detail (debug).** At `LIVING_MEMORY_LOG_LEVEL=debug`, hook lines add `turn`, a 12-character hash of the turn ID, and `detail`: why the hook did what it did, as refs, numbers and reason codes, never text.
- **user-prompt:** `path` is one of `injected`, `all_shown`, `overview_done`, `overview`, `too_short`, `no_overview`, `no_terms` or `machine_prompt`. It also records `terms`, and up to 20 `candidates`, each `{ref, rank, engine, engine_score, relevance, similarity, gate}` where `gate` is `kept:coverage|title|semantic` or `dropped:weak|one_word_no_title|no_informative`. Then `items` (list items found, for a list prompt), `queries`, `injected`, `suppressed_shown` and `cut_by_cap` refs, `overview`, `signal`, `private_spans`, and after a compaction `recall` `{terms, compacted, candidates, hits, used}`.
- **session-start:** `shown`, `indexed`, `degrade` (how far the text was trimmed to fit: `listed`/`of`, `opened`/`open_of`, `width`, `search`, `titles_only`, `tail`, `capped`), `handoff_chars` and `bind_hint`.
- **pre-tool-use:** `tool`, `subcommand`, `decision` (`deny:protected:domains|config|vault`, `deny:subagent`, `allow` or `none`), `mutation` (`tracked`, or `skipped:read_tool|memory_cmd|readonly_shell|subagent|plan_mode|scratch|unknown_session`), `touched` and file-hint refs as `hints`.
- **stop:** `reason` is one of `unbound`, `unknown_session`, `receipt`, `no_change`, `no_turns`, `files_only`, `stop_active`, `already_reminded` or `reminded:<kind>`, where kind is `remember`, `decision`, `directive`, `doc`, `follow`, `explored` or `grown`. It also records `turns`, `mutating`, `signal` and `pending` (the kinds owed).
- **pre-compact:** `trigger` and `steered`.
- **session-end:** `housekeeping`.

Command lines at debug add the result's `status`, `operation_id` and `ref`, and counts of `inferred_tags`, `redacted`, `similar` and `suggested_files`.

**Content logging (sandbox stores only).** With `LIVING_MEMORY_LOG_CONTENT=1`, hook lines add `content` (the prompt, tool input and every text the hook returned), and command lines add `argv`, the result and the error message. Each field has credentials redacted and is capped at 20,000 characters. This happens only when the store holds `sandbox.json` with `{"sandbox": true}` and is not the configured data root. Only the simulation harness writes that file. Otherwise the request is refused: one `content_logging_refused` warning per process, and no text is written.

**Semantic model.** `.models/` holds the model `semantic install` downloaded. It is not canonical, and backups skip it. `semantic remove`, or deleting the folder followed by `rebuild`, returns search to lexical-only. `.models/<name>/tokenizer.marshal` is a derived cache of the parsed tokenizer (rebuilt when missing or stale, safe to delete).

**Currency cache.** `.cache/currency.json` keeps what git said about each shown map or brief (which cited files changed since it was written, commits since), so a new session at an unchanged HEAD runs no git. At most 200 entries, oldest dropped. Derived: safe to delete (it is rebuilt), unreadable content is ignored, and backups, bundles and relocation skip `.cache`.

Stores created by earlier releases may contain an `improvement/` folder (categorical search/read events and engine state). Nothing reads it any more; it is safe to delete by hand.
