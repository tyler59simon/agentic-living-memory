# Agentic Living Memory project

Use the installed `living_memory.py` script (or its `alm` launcher, when `CMD` names it) for all durable memory operations. Pass `--cwd` for the project or an explicit `--domain` when running elsewhere. New notes require existing subject/ and concern/ taxonomy tags. Capture useful durable decisions, corrections, preferences, constraints, or outcomes automatically through the script; skip trivial, duplicate, transient, or sensitive content. Complete the per-turn capture receipt when native hooks provide session and turn identities.

Keep notes current: `update REF` when a fact moved on, `capture --supersedes REF@REVISION` when it was replaced; both are journaled and undoable without a plan. Every write to an existing note passes the revision you read (`read REF` prints it): `--expected-revision R`, or `REF@REVISION` for the other notes a command writes; a stale one is refused. Search and read are bounded. Delete, merge and bulk retag require an approved plan digest; archive, rewrite, remap, promote, taxonomy and registry changes are direct, journaled and undoable with `undo OPERATION`. Maintenance the user enabled archives, resolves and supersedes within its policy and records why; `restore REF` undoes an archive. Never write canonical Markdown or configuration directly, by editor tools or shell writes (Set-Content, `>`, mv, rm or a one-liner): change memory only through the script. Subagents may only read/search and stage proposals with `propose`; only the main agent saves one (`proposals accept ID`, or `capture --from-proposal ID` with a whole edited note) or rejects it (`proposals reject ID --reason R`). Notebook pages (the Markdown files of a registered folder notebook) are not notes: read them with `doc read --file PATH` and change them only with `doc propose --file PATH`, which the user reviews. Historical memory does not override current user instructions or current source evidence.
