# Notebooks: design for Notes Studio (NS-2A, NS-2B)

Hivemind's Notes Studio (roadmap NOTES-1) lets the user keep notebooks either as folders on disk or inside Living Memory. This document is the Living Memory side: a new record kind for notebook pages, notebook-only domains, an attachment store, and agent reach for both notebook kinds. The Hivemind side, and every decision behind this design, is in `agentic-hivemind-app/docs/notes-studio/README.md`. Decisions made by the user on 2026-11-20 are not reopened here.

Two phases: **NS-2A** (records, commands, journal, backup, permissions) and **NS-2B** (search, agent reach, injection, Obsidian sync). Each ships straight to main after the full offline suite, `scripts/simulate.py` and a Codex review; installing still needs the user's approval of the `install.py --plan` digest.

## 1. Pages are not notes

A notebook page is free-form Markdown the user writes. Notes are structured memory with a required summary, a reformatted body, review dates and staleness, maintenance, SessionStart and wiki presence. None of that fits a page, and custom note types cannot opt out of it (every exclusion is a hard-coded tuple of built-in type names; see `core/maintenance.py` `EXCLUDED`, `core/session_start.py` `PRIORITY`, `core/search.py` `RESOLVED_TYPES`). So pages are a separate record kind:

- stored byte for byte (no `format_body`, no summary rule, no frontmatter requirement, no style warnings, no similar-title refusal, no secret refusal beyond a warning);
- never listed by `list`, `review`, `open`, worklists, maintenance candidates, auto-resolve, SessionStart, `recap` or the wiki;
- reached by agents only through `doc` commands and, as each notebook's setting allows, through `search`, `ask` and prompt injection.

## 2. Layout

```text
domains/D/notebooks/<nb>/
  notebook.json            title, order, icons, pinned, visibility, private, created, updated (canonical, journaled)
  <page>.md                a page; any UTF-8 text, kept byte for byte
  <section>/<page>.md      sections are folders
  <page>/<subpage>.md      a folder named like a page holds its subpages
  assets/<sha8>-<name>     attachments, content-addressed prefix
  .proposals/<id>.json     staged agent edits (doc propose)
domains/D/docs.sqlite3     derived page index (NS-2B), not canonical, not backed up
```

- `<nb>` is a slug (`[a-z0-9][a-z0-9-]{1,39}`), unique per domain. `notebook.json` holds `{ "version": 1, "title", "order", "icons", "pinned", "visibility": "hidden" | "searchable" | "injectable", "private": false, "created", "updated" }`; unknown keys are kept.
- Names: each path part 1 to 120 characters; no `/ \ : * ? " < > |`, no control characters, no Windows device names, no leading or trailing space, no trailing dot; unique ignoring case within a folder; depth at most 8; `notebook.json`, `assets` and `.proposals` are reserved at the notebook root. Pages end in `.md`.
- A page's **revision** is the sha256 of its bytes (the same rule as a note's file revision).
- Confinement: `core/docs.py` validates the domain (`canonical_domain`) and the notebook slug before it builds any path, and resolves every page, folder and asset path inside `domains/D/notebooks/<nb>/`; any part that is a symbolic link or junction is refused, so an alias cannot reach another notebook or anything else in the store. `repository.confined` checks parents for symbolic links but not for junctions, so `core/docs.py` checks every part for a reparse point itself.
- Limits: page 4 MiB (`max_page_bytes`); attachment 25 MiB (`max_asset_bytes`); 20,000 pages and 2 GiB of attachments per notebook (doctor warns at 80%).

## 3. Commands (NS-2A)

All output JSON with `--json`. Who may run what is in section 6. Stdin payloads are capped at 1 MiB by `cli._payload` and a `serve` frame at 2 MiB, so Hivemind sends any body over 512 KiB as `--body-file` (a staging file in its app data) and never builds a frame over the cap.

- `--body-file` is read as bytes, unlike `update --body-file`, which decodes with `utf-8-sig` and drops a BOM. The bytes must be valid UTF-8 and at most `max_page_bytes`; anything else is refused before a transaction starts.
- `build_parser` has no nested command groups today; `doc` and `doc notebook` are the first. Each nested parser is built with `common(p, True)`, so `--root`, `--domain`, `--json` and `--actor` work after the verb, and `scripts/gen_script_reference.py` already walks nested parsers. Every `doc` command is listed in `HELP` and in one `HELP_GROUPS` group (`tests/test_render.py`).
- Revisions: `governance.commit` takes its preconditions from the bytes on disk when it runs, so `doc write`, `doc delete`, `doc move` and `doc accept` compare the caller's revision under the store lock (it is re-entrant) and hand it to `repository.transaction` as `expected`. The error message starts with `stale_revision`, which `cli.error_code` reports as `stale` with exit code 6.

| Command | What it does |
| --- | --- |
| `doc notebooks [--domain D \| --all-domains]` | Notebooks with title, domain, visibility, private, page and asset counts, proposals pending |
| `doc notebook create D NB --title T [--visibility V] [--private]` | Creates `notebook.json`; refuses an existing slug |
| `doc notebook update D NB [--title] [--visibility] [--private\|--no-private] [--order-file F] [--icons-file F] [--pinned-file F] [--settings-file F]` | Changes settings, with `--expected-revision` on `notebook.json`; `--settings-file` merges Hivemind's notebook settings (daily folder and format, templates, inbox) into a `settings` object |
| `doc notebook delete D NB` | Refused while pages exist unless `--with-pages`, which goes through a plan (`plan` and `apply`), like note deletion |
| `doc list D NB [--section S]` | Pages and folders with size, revision, updated |
| `doc read D NB PATH [--max-chars N]` | `{ path, text, revision, size, updated }`; `truncated` past the cap |
| `doc create D NB PATH [--body-file F]` | New page; refuses an existing path |
| `doc write D NB PATH --expected-revision R [--body-file F]` | Replaces the page; `stale` (exit 6) on a mismatch |
| `doc move D NB FROM TO [--rewrite-links]` | Renames or moves a page or folder; with `--rewrite-links`, `[[...]]` links to it in the same notebook are rewritten in the same transaction (at most 200 pages) |
| `doc delete D NB PATH --expected-revision R` | Deletes a page (journaled, undoable) |
| `doc attach D NB --from-file PATH [--name N]` | Copies a file into `assets/` (Living Memory reads the file itself, so the bridge never carries the bytes); returns the relative link |
| `doc history D NB PATH [--limit N]` | Journal entries touching the page, newest first, with operation id, kind, time, before and after revisions; `--version OP` returns that version's text |
| `doc undo OPERATION` | Through the existing `undo` (the `doc_` prefix joins `DIRECT_UNDO_PREFIXES` in `core/governance.py`) |
| `doc propose D NB PATH --base-revision R [--body-file F] [--note TEXT]` | Stages an edit (agents may run it) |
| `doc proposals [D [NB]]`, `doc accept ID [--expected-revision R]`, `doc reject ID [--reason TEXT]` | Lists, applies or drops staged edits; accept and reject are main-actor only |
| `doc search QUERY [--domain D \| --all-domains] [--notebook NB] [--include-private] [--rebuild]` | NS-2B; hidden notebooks are searched only when `--notebook` names one; private ones only with `--include-private` (section 6) |
| `doc tasks [--domain D \| --all-domains] [--notebook NB] [--open]` | NS-2B; task lines (`- [ ]`, `- [x]`) with page, line, text and due date, from the index |
| `doc query --payload-file F` | NS-2B; pages filtered and sorted by frontmatter properties (`{ "where": [...], "sort": [...], "limit": N }`), from the index |
| `doc folder set PATH --visibility V [--private\|--no-private] [--domain D]`, `doc folder unset PATH` | NS-2B; the folder notebook policy registry (section 8.2) |

Every write is one `repository.transaction` with a kind starting `doc_` (`doc_create`, `doc_write`, `doc_move`, `doc_delete`, `doc_attach`, `doc_notebook`, `doc_propose`, `doc_accept`, `doc_reject`, `doc_folder`). Each `doc_` journal records the domain and notebook id, so later redaction (section 6) still knows which notebook an operation touched after the notebook is renamed or deleted.

## 4. Journal and storage changes

- `core/repository.py` `_write` decodes every payload as UTF-8, which breaks attachments, and recovery rebuilds every effect from the journal's before and after images. Attachments therefore get a binary effect of their own (`"blob": true`, with `before` and `after` null and only the two hashes kept): the bytes are first written to `.operations/<op>/blobs/<sha256>` and fsynced, then the intent is journaled, then recovery moves the blob into `assets/`. Whatever the asset path held before is moved aside into the same `blobs/` folder first, so either side can be restored; when two effects of one operation want the same bytes, all but the last get a copy. Effects are ordered by their hash (writes before removals), since a blob effect keeps no content. Recovery refuses with "Attachment bytes are missing" when the wanted bytes are in neither place, and `recover OP --abandon` drops the operation. `doc attach` of bytes already present under the same name writes nothing and returns `created: false`. Undo of an attach moves the asset into the undo operation's `blobs/` folder, so undoing the undo brings it back. Assets are immutable and content-addressed (`<sha8>-<name>`), and deleting a page never deletes an asset another page links. `governance.py` reads `blob` effects without decoding them.
- Journals keep base64 before and after images and `prune_journals` never prunes edit kinds. Pages would grow `.operations/` without bound, so `doc_` journals get their own retention (`docs.prune_journals`): a finished `doc-` operation goes once it is not among the newest 100 operations of any file it changed, or once it is older than 90 days, whichever comes first. Claude chose "first" over "whichever keeps more" while writing NS-2A on 2026-11-20: with Hivemind saving on idle, "keeps more" holds every save of the last 90 days, each with the page text twice, so a page edited daily would grow the store by gigabytes. Pruning removes the operation folder with its `blobs/`, so an undo of a pruned operation is refused like any missing journal. Each `doc-` operation writes a small `doc.json` (created, paths) beside its journal so retention does not read page text; without it, the journal is read. Pruning runs where `prune_journals` runs today.
- Undo of a page write restores the before bytes with the after revision as precondition, as for notes.
- Pages are UTF-8 text, so they use the existing text effect: `_write` decodes the bytes and writes them in text mode with `newline="\n"`, which keeps CRLF and a BOM byte for byte. A body that is not valid UTF-8 is refused up front, because `transaction` accepts any bytes and `_write` would only fail during recovery, leaving a pending operation.
- `doc` writes call `repository.transaction` (or `governance.commit` with no domains), so they never run `reconcile`: a notebook-only domain has no notes to index, and `reconcile` rejects a domain without `notes/`.
- `governance.undo` changes in three ways: `blob` effects are restored as bytes (today it decodes every before image as UTF-8); only paths under `domains/D/notes/` and `domains/D/archive/` name a domain to reconcile, so undoing a `doc_` operation reconciles nothing; and `doc_` joins `DIRECT_UNDO_PREFIXES`.
- `governance.plan` stores its changes as JSON text. A plan that carries attachments (a restore, or `doc notebook delete --with-pages`) stages their bytes under `.plans/<id>/blobs/<sha256>` and records `{ "blob": "<sha256>" }` for each; `apply` turns those into `blob` effects. Deleting needs no bytes.

## 5. Notebook-only domains

- `core/init_domain.py` gains `init_notebook_domain(name)`: writes `bindings.json` domain entry `{ "prefixes": [], "notebook_only": true }` and creates only `domains/NAME/notebooks/`. Command: `domain create NAME --notebook-only` (main actor).
- Verified interactions: `resolve_domain` never resolves a domain without prefixes; every `--all-domains` path that filters on `domains/D/notes` being a folder skips it (`cli.py` `list`, `links`, `review`, `open` and `recap`, `maintenance enable --all-domains`, `semantic.rebuild_all`). Paths that walk `domains/` without that filter (`doctor`, `governance.py`, `migration.py`, `session_start.py`, `notes.py`) are checked one by one and skip or accept notebook-only domains; `doctor --domain NB` must not report a notebook-only domain as missing (its `domain_exists` requires `notes/` today).
- Needed changes: `capture`, `propose` and `update --domain` refuse with "D holds notebooks only"; `unbind` refuses while pages exist; `bind NAME FOLDER` on a notebook-only domain drops `notebook_only` in the same journaled change to `bindings.json` and then creates `notes/` and `archive/`, as `init_domain` does for any domain (folders are not journal effects); a conversion that stopped after the transaction leaves a bound domain without `notes/`, which `doctor` reports and running the same `bind` again finishes; `domains` reports `kind: "notebook"` (and `kind: "memory"` for others) with page counts.
- Validation and relocation are kind-aware: `validate.py` and the relocation check (`storage.py`) accept a domain with `notebook_only` and no `notes/`, and reject one without the flag as today. `apply_relocation` creates `notes/` and `archive/` in every domain and reconciles each; it skips notebook-only domains. `relocation_plan` counts notes by the `domains/D/notes/` and `domains/D/archive/` prefixes instead of any path containing `/notes/`, since a notebook section may be called `notes`.
- Obsidian mirroring (section 8.4) of a notebook-only domain starts the same way as for any domain, with `sync --domain DOMAIN VAULT` (run from any folder), which records the vault in its `sync-state.json`; Hivemind offers the domain's vault choice in notebook settings (NS-2C).

## 6. Permissions

Trust model: `--actor` is self-declared (it defaults from `LIVING_MEMORY_ACTOR`), so it is not a security boundary. Living Memory tells agents apart in two ways only: its PreToolUse hook, which classifies every command an agent runs, and `HIVEMIND_SESSION`, which agents inside Hivemind terminals inherit and Hivemind's own bridge does not. An agent can still read files it can reach with its own tools; Private stops Living Memory from offering the content, it does not protect files.

- **Reads** (`notebooks`, `list`, `read`, `history`, `proposals`, `search`, `tasks`, `query`) are allowed for every actor, and `doc search --rebuild` too (it writes only the derived page index, as `search --rebuild` does for notes).
- **Private notebooks** are left out of every read, search, task, query and proposal listing unless the command carries `--include-private`. Hivemind's bridge passes it. The hook denies any agent command that carries it, and it does so before its early return for sessions with no bound domain; `cli.py` refuses it when `HIVEMIND_SESSION` is set.
- **Redaction:** generic `history`, `diff`, `inspect-plan` and `proposals` redact every effect whose path lies under a private notebook, whatever the operation kind (`doc_` writes, `restore`, `apply`, recovery), unless `--include-private` is given. Privacy follows a durable identity: each `notebook.json` gets an immutable `uid` at creation, journals record it, and `<store>/notebook-privacy.json` keeps the `uid` and last path of every notebook that was ever private, including deleted ones, so a reused slug or a deleted notebook never exposes an old private operation.
- **Hidden notebooks** are readable by an explicit `doc read` or `doc list` naming them, and searchable by `doc search`, `doc tasks` and `doc query` with `--notebook` naming them; they are never returned by `search`, `ask` or injection, or by `doc` commands that do not name them.
- **Writes:** `propose` is allowed for main and agents (not viewers). Every other `doc` write, `doc folder set` and `unset`, and `domain create` are main-actor writes. In `cli.py`, `doc` joins `READ_ONLY` and `VIEWER`, and its write actions are refused per action for subagents and viewers, as `proposals reject` is, except `doc propose` for subagents. In the hook, a detector `doc_write(text, grammar)` modelled on `views_write` returns true for them and feeds three places in `core/runtime.py`: `memory_write`, which denies subagents; the auto-allow test, which leaves out `doc` writes as it leaves out `taxonomy` writes, so they are never auto-allowed; and the Hivemind terminal rule. `HIVEMIND_GOVERNED` matches whole verbs, so the check is `subcommand == 'doc' and doc_write(...)` plus `domain create`, which keeps `doc propose` allowed inside Hivemind terminals; its token fallback for commands it cannot parse gains the same `doc` write verbs.
- **Paths:** `protected_rule` already denies agent edits under `<store>/domains`; NS-2A adds `notebook-folders.json` and `notebook-privacy.json` to its protected config files. NS-2B adds the vault's `Notebooks` folder to the protected vault folders, and the hook runs the notebook path check before its early return for sessions with no bound domain (today `runtime.py` returns before the protected-path guard for unbound sessions). The hook also denies an agent's file-reading tools (Read, Grep, Glob) on `domains/*/notebooks/<nb>/` of a private notebook; a shell command can still read it, as stated in the trust model. Claude Code sends Read, Glob and Grep through `core/hookfast.quick` first, which can answer without the runtime, so the check goes there too. Likewise, the hook sees agents' structured edit tools, not files a shell command writes: "agents may only propose" covers Living Memory commands and structured tools, and a shell write into a vault notebook is synced as a user edit, the same limitation notes have today.
- `core/instructions.py`: the protocol gains two sentences: read pages with `doc read`, change them only with `doc propose`, which the user reviews. The fallback protocol has 4 characters left under its 3,400-character cap (`tests/test_help.py`), so the new sentences replace wording elsewhere in it rather than adding to it.

## 7. Backup, bundles, relocation, doctor

- `core/backup.py`: a snapshot today is a zip of the canonical files with no manifest. NS-2A adds `manifest.json` (version 2), and a snapshot without one counts as version 1. The manifest lists what the snapshot covers (`notes`, `notebooks: [D/NB, ...]`) and what it left out (`omitted: [{ path, reason }]`, for attachments over the automatic-backup budget). `MEMBER` gains `domains/D/notebooks/<nb>/(notebook.json|**/*.md|assets/**|.proposals/*.json)`; `canonical_files` includes them; attachments are stored with `ZIP_STORED` and read back as bytes (restore no longer decodes every member as UTF-8). Restore never deletes a file the snapshot does not cover: a version 1 snapshot, or a notebook absent from a version 2 snapshot, leaves the live notebook untouched, and omitted attachments are kept. When a restored `bindings.json` lacks a domain that still holds uncovered notebooks, restore keeps that domain's live entry (merging it into the restored file), so a notebook-only domain is never dropped. Plan apply, transaction recovery and undo handle `blob` effects as bytes (section 4). Restore plans, `inspect-plan` and `diff` handle binary members as hashes and sizes, never decoded text. Every note-count predicate (`_note_count`, `SHRINK_MIN` and the shrink checks, `maybe_backup`) keeps counting notes only; today each counts every `.md` member. `verify` routes members by path: notes must parse as notes, pages must decode as UTF-8, `notebook.json`, proposals and the manifest must be JSON, and attachments are checked for size only. Today `restore_plan` deletes canonical files of a covered domain that the snapshot lacks; for notebooks, covered means listed in the manifest. Automatic backups skip attachments over an asset budget (default 500 MB per snapshot) and list them in `omitted`; manual `backup` includes everything.
- `core/bundle.py`: bundles carry notes only in NS-2A, so import refuses a notebook-only target domain ("D holds notebooks only"). Exporting notebooks in bundles, with a separate `MAX_ASSET` (25 MiB) and a bundle total cap, is left for a later phase.
- Relocation (`core/storage.py`): copies notebooks and assets; leaves out every derived index with its `-wal` and `-shm` files, `docs.sqlite3` included, and the destination rebuilds them (today the side files of `sources.sqlite3` and `vectors.sqlite3` are copied, which this fixes too); validates notebook-only domains (section 5).
- `doctor`: unreadable `notebook.json`, pages over the limit, orphaned assets (no page links them; listed, never deleted automatically), notebooks near their caps, proposals older than 30 days, a half-converted notebook-only domain, folder policy entries whose folder is gone.

## 8. Search and agent reach (NS-2B)

### 8.1 One result shape for both notebook kinds

- `search` and `ask` gain a `pages` array after `results` and `notes`: `{ origin: "lm" | "folder", domain, notebook, title, path, heading, snippet, line_start, line_end, revision, score, label: "notebook page" }`. For several questions, each entry in `questions` gains its own `pages`. Folder notebook chunks appear only in `pages`, never in `sources`, and `search --sources` keeps returning non-notebook sources only. Existing fields keep their meaning, so current parsers are unaffected.
- Filtering, for every actor: private notebooks only with `--include-private`; hidden notebooks never; searchable and injectable ones always.
- Living Memory pages: `core/docs_index.py` keeps a derived `domains/D/docs.sqlite3` with `pages(path, notebook, revision, title, updated, size, mtime)`, an FTS5 table over chunks (title, heading path, text; `porter unicode61`), `tasks(page, line, done, text, due)`, `props(page, key, value)`, and vectors per chunk when a semantic model is installed. Chunking reuses the heading-aware chunker of `core/sources.py`. Freshness does not depend on any write path: every `doc search`, `doc tasks`, `doc query`, `search` and `ask` first runs a stat walk of the domain's notebooks (as `sources.py` does for sources), at most 0.2 s, resuming from a saved cursor on the next call, then reindexes changed pages for at most 0.5 s and leaves the rest pending; a result that ran on an unfinished walk carries `pages_stale: true`. Undo, restore and recovery therefore need no hook of their own. `doc search --rebuild` rebuilds the file.
- Pages never enter `search.sqlite3`'s notes table, so `search_domains`, `relevance_gate`, vocabularies, SessionStart and maintenance are untouched.

### 8.2 Folder notebooks: the policy registry

Folder notebooks live outside the store; Living Memory reaches them through sources (`core/sources.py`). Their reach is decided by a policy registry, with the sidecar as a second opinion:

- `<store>/notebook-folders.json`: `{ "version": 1, "folders": [{ "path": "<canonical plain path>", "domain": "D", "visibility": "hidden" | "searchable" | "injectable", "private": bool, "updated": "<iso>" }] }`. Identity is the canonical path compared in lowercase. `doc folder set` adds or updates an entry (idempotent: an unchanged entry writes nothing) and `doc folder unset` removes it; both are journaled (`doc_folder`) and undoable. Hivemind calls `set` when a notebook is registered and whenever its reach changes, and `unset` when it is removed. `unset` of a hidden or private entry keeps it as a tombstone (`removed: true`), so the folder stays excluded even when its sidecar could not be written; only `doc folder unset --forget`, which Hivemind sends when the user removes a notebook and also chooses to make it searchable again, deletes the entry.
- The effective policy of a folder is the stricter of its registry entry and its sidecar `.hivemind/notebook.json` (private beats everything; hidden beats searchable beats injectable). A sidecar that exists but cannot be parsed counts as hidden. A notebook folder found by its sidecar but absent from the registry uses the sidecar alone; one in neither is an ordinary folder, as today.
- A registered folder outside every bound repository is indexed as a source of its domain (no `source add` needed); one inside a bound repository is indexed by the implicit repo source, with the policy applied to its subtree.
- Indexing: `walk` skips hidden and private notebook subtrees entirely; chunks gain `notebook` (the canonical folder path) and `inject` columns; `VERSION` goes up, so the next sync rebuilds.
- Retrieval: policy is checked again when results are served, on every path (lexical and semantic `search`, `ask`, injection, digests and ingest), against the current registry and sidecar (cached by the files' mtimes), so a notebook made hidden or private disappears at once even before a sync. A policy change also purges that notebook's rows and vectors at the next sync, tracked by a policy revision kept apart from content hashes.

### 8.3 Injection

- UserPromptSubmit adds up to two source excerpts (800 characters) when notes gave fewer than two answers. Notebook excerpts use that channel and inherit all of its rules: no injection for subagents or machine prompts, each excerpt at most once a session, and only when the block fits the 4,000-character prompt budget of `core/injection.py`.
- Only chunks of injectable, non-private notebooks are candidates; they are labelled `[notebook TITLE]`. Living Memory pages of injectable notebooks in the session's scope domains join the same channel, after notes. Searchable notebooks are never injected.
- SessionStart is unchanged, and a test asserts that no page or notebook excerpt ever appears in it.

### 8.4 Obsidian sync

`core/sync.py` mirrors each searchable or injectable, non-private notebook byte for byte to `<vault>/Notebooks/<domain>/<nb>/` with its assets (pages are never rewritten by `build_overlay`). Hidden and private notebooks are never mirrored, and a notebook that becomes hidden or private has its mirror removed at the next sync. Edits in the vault come back after the existing 30-second quiet period as `doc write --expected-revision <last synced revision>`; a conflict becomes a `doc propose` with the vault text instead of an overwrite. New `.md` files under a vault notebook become pages; deleted files become a pending deletion on the Sync Status page, like notes. Vault edits are trusted as the user's edits, the same rule as notes today; the vault's `Notebooks` folder joins the folders agents may not write. Every source walk excludes `<vault>/Notebooks` of each managed vault by canonical identity, including sources rooted inside the vault, so a mirrored page is never indexed twice or outside its policy. The same exclusion is applied to cached rows when results are served, and when a vault becomes managed, rows already indexed under its `Notebooks` folder are purged.

## 9. Version capability

`version` capabilities gain `docs: { "version": 1, "max_page_bytes": 4194304, "max_asset_bytes": 26214400, "notebook_only_domains": true }` in NS-2A, and `"search": true, "folder_policy": true` in NS-2B. `tests/test_restore.py` asserts the whole capabilities dictionary and must be updated; SCRIPT_REFERENCE.md documents the object.
