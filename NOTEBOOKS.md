# Notebooks

Notebooks hold pages: free-form Markdown the user writes, mostly in Hivemind's Notes Studio. Living Memory knows one kind of notebook, the folder notebook: a registered folder of Markdown files outside the store. Pages are a record kind of their own. They are not notes, so no list, review, maintenance, SessionStart, recap or wiki path reads them, and they need no frontmatter or tags. `search` and `ask` list them apart from notes, in a `pages` array. The design is in `docs/notebooks-design.md`; its sections on hosted notebooks are historical.

Hosted notebooks, which kept their pages inside the store (`domains/D/notebooks/<notebook>/`), were retired in CON-18 on 2026-11-24. Their `doc` commands (`notebooks`, `notebook create|update|delete`, `list`, `create`, `write`, `move`, `delete`, `attach`, `history`, `tasks`, `query`, and the `DOMAIN NOTEBOOK PATH` forms of `read` and `propose`) and `domain create --notebook-only` fail as unknown commands, with no aliases. A backup that still holds `notebooks/` folders or `notebook-privacy.json` verifies and restores with those parts dropped.

## Commands

| Command | What it does |
| --- | --- |
| `doc read --file PATH [--max-chars N]` | A Markdown page of a registered folder notebook: `origin: folder`, `domain`, `notebook` (the `nb-` id), `folder`, `path` (inside the folder), `file`, `text`, `revision` (sha256 of the bytes, as `search` gives it), `size`, `updated`. A private folder reads as not found |
| `doc propose --file PATH [--base-revision R] [--note TEXT] [--body-file F]` | Stage an edit for the user (agents may run it): the base revision must match, a page is at most 4 MiB, a possible credential is warned about, and leaving out the base revision means a new page. The proposal is kept at `domains/D/folder-proposals/NB/ID.json` with the page as it was read (`base`, up to 1 MiB) so Hivemind can merge against it |
| `proposals [list] [--kind note\|page\|all] [--status pending\|accepted\|rejected\|all] [--domain D] [--notebook NB]`, `proposals show ID` | Staged page edits (12 hex digit IDs; each row has `kind: page`) and staged notes (8 digits; `kind: note`) |
| `proposals accept ID [--expected-revision R]`, `proposals accept ID --edited [--expected-revision R]` (body from `--body-file` or stdin), `proposals reject ID [--reason TEXT]` | Settle a staged page edit (main actor). `--edited` writes the user's merge of it instead and settles it as accepted and edited in one operation; the page must be at `R`, or not exist when `R` is left out. The merge must be given (a terminal or a serve request without stdin is refused) |
| `search WORDS --pages [--all-domains] [--limit N]` | Search the pages of folder notebooks; a hidden or private notebook never |
| `doc folder set PATH [--visibility V] [--private\|--no-private]`, `doc folder unset PATH [--forget]` | Register a folder notebook outside the store and how far agents reach into it (Hivemind runs these) |
| `doc undo OPERATION` | Undo a folder notebook operation (a proposal, a settlement); `undo OPERATION` does the same |

Page names follow one rule everywhere: each part of a path is 1 to 120 characters, with none of `/ \ : * ? " < > |` or a control character, no leading or trailing space or trailing dot, and no Windows device name.

## Who may do what

- Agents read pages (`doc read --file`, `search --pages`, `proposals list` and `show`) and stage edits with `doc propose --file`. Every other `doc` action, an unknown one included, is the main actor's: the hook denies it to subagents, never auto-allows it, and denies it to agents in a Hivemind terminal (`HIVEMIND_SESSION`). The hook also denies `serve` to agents, since its requests carry arguments the hook never sees.
- Visibility: a `hidden` notebook is never found by `search` (with or without `--pages`) or `ask`, but its pages can be read and proposed to by naming the file. A `searchable` one (the default) is found by `search`, `search --pages` and `ask`. An `injectable` one is also offered to the prompt hook (see below).
- Private notebooks look missing to `doc read --file`, `doc propose --file`, `proposals` and the commands that undo or recover their operations, unless the command carries `--include-private`, which only Hivemind's own bridge passes. The flag is gone from `search`, `ask` and `doctor`, which never served private pages. Inside `batch` the flag is refused, because the hook sees only the outer command. The hook denies the flag to any agent. It reads only the option words of a `living_memory.py` or `alm` command: the flag text inside a quoted value (a note's summary), and other programs' options such as `grep --include=*.py`, do not count. `history` (note history too), `diff` and `inspect-plan` leave out the registry, the staged page edits and the retired mirror's state file (`domains/D/notebook-sync.json`) unless `--include-private` is given. Private is not file protection: a shell command can still read the files.

## Folder notebook pages

- `doc read --file` and `doc propose --file` take the path of a `.md` or `.markdown` file under a registered, not removed folder (the nearest one wins). A link or junction on the way is refused. A hidden folder can be read and proposed to by naming the file; a private one looks missing without `--include-private`.
- The hook refuses an agent's Edit, Write, MultiEdit, NotebookEdit or apply_patch on such a page and says to read it with `doc read --file` and stage the edit with `doc propose --file`; for a private folder it says agents may not change it. The rule covers every agent session, Hivemind's or not (`runtime.FOLDER_GUARD = 'all'`). The registry is cached by its modification time, since the hook runs on every edit.
- Not covered: shell writes, copies of the folder (a git worktree stays a code diff), folders known only from a `.hivemind` sidecar and sessions that turned Living Memory off. A damaged `notebook-folders.json` guards nothing until `doctor` repairs it.
- `proposals accept ID` settles the record first (`doc_accept`, journaled, with the new bytes' `revision`), then writes the page with the safe write the Obsidian sync also uses: CRLF and a BOM are kept exactly, and a save made meanwhile is never overwritten. A page that changed since the proposal's base revision is refused (`stale_revision`, exit 6); with `--edited` the page must be at `--expected-revision` instead, and the record keeps the bytes the merge replaced (`previous`). If the write finds the page changed, the settlement is undone and the accept is refused. Running `proposals accept ID` again on an accepted proposal whose page was never written finishes the write. A proposal whose folder is no longer registered is `orphaned`: it can be rejected, not accepted.
- `accept` and `reject` take the proposal's notebook and domain from where its file was found (`domains/D/folder-proposals/NB/ID.json`), never from the `domain` and `notebook` fields inside the record, so a hand-edited record cannot send the settlement to another path.
- `undo OPERATION` on a folder `doc_accept` puts the old bytes back while the page still holds what the accept wrote (a new page is deleted again), then sets the proposal back to pending. After a later change to the page it is refused and says to restore the page from Hivemind's file history. A second undo, or an undo of the undo, changes nothing; accept the proposal again instead.
- `history` hides these operations unless `--include-private` is given: the records hold page text from outside the store. `doc undo` handles them.

## Search and reach

- Folder notebooks are folders outside the store that Hivemind opens as notebooks. `doc folder set` records one in `notebook-folders.json` with its domain, visibility and private flag; its sidecar `.hivemind/notebook.json` (`visibility`, `private`, `title`) is a second opinion, and the stricter of the two wins (private, then hidden, then searchable, then injectable). A sidecar that cannot be parsed counts as hidden; a folder inside a notebook takes the strictest policy above it. `doc folder unset` of a hidden or private folder keeps its entry as a tombstone, so the folder stays out of reach even where the sidecar was never written; `--forget` drops it. `set` keeps a tombstone's private flag unless `--no-private` is given, and without `--visibility` it keeps the entry's or tombstone's visibility (a new folder is searchable; capability `docs.folder_policy` 2), and a restore never replaces a live entry with a less strict one. Folders are judged by their resolved path, so a link or junction to a private folder reaches nothing in it. `set` refuses a folder that is, holds or lies inside the Obsidian vault Living Memory manages. Of two registry rows for one folder (an alias, a hand edit), the stricter counts for reads, `set`, `unset` and restore alike. The registry is Hivemind's bookkeeping: `history`, `diff` and `inspect-plan` show it only with `--include-private`. An undo, plan or restore that would make a hidden or private folder less strict needs `--include-private` too; other changes to them do not.
- Folder notebook pages are indexed by the knowledge base (`core/sources.py`): by a source without include globs that already walks the folder, else by a source of their own named `nb-` and a hash of the path (a page that two sources index is served once). Hidden and private notebooks are never walked. Each hit is checked again against the registry and sidecars when it is served, so a notebook made hidden or private disappears before the next sync, and its rows go at that sync; a source whose link or junction now leads elsewhere serves nothing until it is synced again, and that sync reads every file afresh. A source with include or exclude globs inside a notebook does not stop the notebook's own source from walking that folder too. A folder notebook moved to another domain is served only by the domain the registry names. `search --sources`, `ask`'s `sources` and `ingest-scan` leave every notebook file out, and `--source` refuses a file in a hidden or private notebook. A digest made from a file before its notebook turned hidden or private is withheld: search, ask and the prompt hook show a WITHHELD notice and the title "Withheld note" in its place until the user reviews it, also when the file has since been deleted (the note itself stays memory). `search --file` withholds it the same way. A damaged `notebook-folders.json` (unreadable, or a row without an absolute path, with an unknown visibility or a private flag that is not true or false) stops `source-sync`, serves no source excerpt or folder page and withholds every digest made from a file until doctor's warning is acted on. `sources` counts only the files of notebooks that are searchable or injectable now, and says `folder moved` for a source whose link now leads elsewhere.
- Each page hit has `origin: folder`, `domain`, `notebook`, `notebook_title`, `title`, `path`, `file`, `heading`, `snippet`, `line_start`, `line_end`, `revision`, `score`, `relevance` and `label: notebook page`. `ask` gives each question of a several-question query its own `pages`. A folder page is chunked like any source file, so its snippet can show frontmatter lines. Credentials are redacted as in sources. With a semantic model installed, a page that shares no word with the query is listed only when its chunk is at least the model's `min_similarity` (0.45 for potion-retrieval-32M) close in meaning. Without that floor the nearest chunks filled every result with score -0.0 and relevance 0.0.
- Prompts: the prompt hook's source excerpt channel (at most two excerpts, 800 characters, only when notes gave fewer than two answers, never for subagents or machine prompts, each excerpt once a session) also takes excerpts of injectable folder notebooks of the session's domain. Each is labelled `[notebook TITLE]`. Searchable notebooks are never injected, and SessionStart shows no page text; its Overdue line may name an overdue task of an injectable page (see [Tasks](#tasks)).

## Tasks

- A page line `- [ ] text` or `- [x] text` is a task (the bullet may also be `*`, `+` or `1.`), outside fenced code and frontmatter. It has three optional fields, read by the rule that also reads the action items of notes (`item_fields` in `core/note_format.py`): `due` (`YYYY-MM-DD`), `owner` and `priority` (`highest`, `high`, `medium`, `low` or `lowest`).
- Write them as a tail at the very end of the text, in any order: `- [ ] Call Sam (due: 2026-12-01, owner: me, priority: high)`. A field the tail does not give validly is read from the text: `due` from the first `📅 2026-12-01` or `due:: 2026-12-01`, `priority` from the first of `🔺` (highest), `⏫` (high), `🔼` (medium), `🔽` (low) or `⏬` (lowest). `owner` is the tail only. When both forms are there, the tail wins. A bad value is ignored. Changing a page's tasks is a page edit (`doc propose --file`), not an `update --item`.
- `text` is what follows the box, cut at 500 characters; the fields are read from that text. `task` is the text people read: `text` without the tail, a `📅 date`, a priority emoji and a `✅ date`. The cases are in `tests/fixtures/task_lines.json`, which Hivemind copies and runs through its own parsers.
- `open` lists open page tasks beside the open action items of notes, as rows with `kind: "page"`, `domain`, `notebook`, `path`, `title`, `line`, `item`, `task`, `due`, `owner`, `priority` and `overdue`; a page task has no `ref` or `index`, and is ticked by editing its page. `--pages injectable` (the default) takes the injectable folder notebooks of the domain and its parents, `--pages searchable` also the searchable ones and `--pages none` leaves page tasks out. Hidden and private notebooks never show. `--tag` lists no page tasks (they have no tags). `--due-by`, `--owner` and `--sort due` apply to both kinds. `pages_stale: true` says the page index was left unfinished.
- Registered folder notebooks are indexed in `domains/D/docs.sqlite3`, named `nb-` and ten hex digits of the folder's path as in the knowledge base. Only `meta`, `source`, `file` and `task` tables exist, with no chunks, search text, vocabulary or vectors, since page search comes from the knowledge base. The walk skips dot folders (`.hivemind`, `.obsidian`), links and pages over 1 MiB. Only `open` and SessionStart read this index. Each page is judged when it is served by the strictest policy over its folder and the folders above it (registry and sidecars), so a hidden or private subfolder never shows, whatever the index holds. `open` first checks the notebooks for changed pages for at most 0.2 seconds, resuming where the last check stopped, then reindexes for at most 0.5 seconds; each call still finishes one notebook and one page past those limits, so it always makes progress (with several domains, they take turns, recorded in `hooks/docs-allowance.json`). The index is derived and never backed up. It has `VERSION` 3 (2 added `owner` and `priority`; 3 dropped the chunk, search and property tables); an index of another version is replaced on the next refresh.
- SessionStart reads the page index as it is and never indexes: the Overdue line also counts and names (as `path:line`) overdue open tasks of injectable pages, and an unreadable, missing or older index shows none.

## Obsidian

The Obsidian page mirror, which copied hosted notebooks to `<vault>/Notebooks/`, is gone. Its copies in a vault are plain files now and stay where they are; Living Memory keeps the folder hidden from agents and never indexes it as a source. A leftover `domains/D/notebook-sync.json` is ignored and removed by the next `sync`, `overlay-build` or vault sync of that domain.

## Journals, backups and relocation

- Every folder notebook write is one journaled operation (`doc-...`, kinds `doc_propose`, `doc_accept`, `doc_reject`, `doc_folder`). A finished operation is deleted once it is not among the newest 100 operations of any file it changed, or once it is older than 90 days; this runs with the daily journal pruning. The journals of retired hosted operations keep the `doc` label and, when they only changed text, still undo like any plain write; one that moved an attachment, or left a page in an encoding other than UTF-8, is refused with a message that hosted notebooks were retired.
- Snapshots carry `manifest.json` (version 3). `notebook-folders.json` is backed up and restored, and a restore never replaces a live entry with a less strict one.
- Relocation leaves out every derived index (`search`, `sources`, `vectors` and `docs` SQLite files with their `-wal`, `-shm` and `-journal` files, and their `.sources-`, `.vectors-` and `.docs-` temporary files).
